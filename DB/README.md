# Maollar 数据库变更基准

生产数据库不是全新安装库，不能直接用上游完整 SQL 覆盖。所有结构变更都必须先备份相关表，再执行可重复运行的迁移，最后验证应用健康和关键业务链路。

## 当前生产补丁

`hotfix_20260715_commerce_schema_reconcile.sql` 是 2026-07-15 商城验收后的结构对齐基准，覆盖：

- 商品分类详情字段；
- 订单明细的发货与退款字段；
- 运费模板和店铺物流字段；
- 订单包裹表；
- 上游 4.3 到 4.4 遗漏的分销提现字段。

该脚本已在生产 MySQL 8.0.30 连续执行两次通过。脚本是幂等的，不写入店铺、地址、物流凭证等业务数据；末尾校验查询应返回零个缺失字段和零个孤立店铺引用。

## 执行规则

1. 先导出将受影响的表，并记录备份路径与文件大小。
2. 在当前数据库上执行对应迁移，不使用完整初始化脚本覆盖生产数据。
3. 再执行一次迁移，确认幂等。
4. 检查迁移末尾的验证结果。
5. 通过 `ops/release-module.sh` 发布受影响服务，并完成健康检查和业务回归。

MySQL 8.0.30 不支持本项目旧脚本使用的 `ADD COLUMN IF NOT EXISTS` 写法；新增补丁应沿用当前文件中的信息架构检查方式。
